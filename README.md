# Календарь звонков

[![hexlet-check](https://github.com/islamka13/ai-for-developers-project-386/actions/workflows/hexlet-check.yml/badge.svg)](https://github.com/islamka13/ai-for-developers-project-386/actions)

Сервис бронирования времени по мотивам Cal.com. Владелец календаря публикует доступное время для встреч, гость выбирает свободный слот и записывается на звонок — без регистрации и авторизации.

Учебный проект Хекслета: https://ru.hexlet.io/programs/ai-for-developers
Как это должно работать: https://files.hexlet.app/a/2ipc5m

## Роли

- **Владелец календаря** — один заранее заданный профиль. Заводит типы встреч и смотрит список предстоящих встреч.
- **Гость** — любой посетитель без аккаунта. Выбирает тип встречи и бронирует свободный слот.

## Сценарий: от создания типа встречи до записи в списке владельца

### Владелец

1. Владелец открывает админскую страницу и создаёт тип встречи: задаёт название (например, «Знакомство»), описание и длительность в минутах (например, 30).
2. Тип встречи сохраняется и становится доступен гостям на странице записи.

### Гость

3. Гость заходит на главную страницу и переходит на страницу записи.
4. Видит каталог типов встреч: название, описание и длительность каждого типа.
5. Выбирает тип встречи — открывается календарь на ближайшие 14 календарных дней.
6. Видит свободные слоты в рабочие часы владельца. Длительность слота равна длительности выбранного типа встречи.
7. Выбирает свободный слот и подтверждает запись.
8. Получает подтверждение бронирования. Если слот уже занят (в том числе встречей другого типа), видит понятное сообщение о конфликте.

### Владелец (проверка)

9. Владелец открывает страницу предстоящих встреч и видит новую запись в общем списке встреч всех типов.

## Ограничения

- Нет авторизации, личных кабинетов и интеграций с внешними календарями.
- Одно и то же время нельзя занять дважды, даже разными типами встреч. Примыкание допустимо: следующая встреча может начинаться в момент окончания предыдущей.
- Окно записи — 14 календарных дней, сдвигается с текущей датой. Начало окна, рабочие часы, часовой пояс и шаг доступных стартов фиксируются в спецификации.
- Данные хранятся в памяти процесса: перезапуск приложения сбрасывает записи.

## Стек

- **Фронтенд:** React + Vite + TypeScript, shadcn/ui
- **Бекенд:** Hono (TypeScript)
- **API-контракт:** TypeSpec → OpenAPI → клиентский SDK для фронтенда
- **Публикация:** Docker-образ, деплой на Render

## Установка

Требуется [mise](https://mise.jdx.dev/) — он ставит Node.js и остальные инструменты версий из `mise.toml`.

```bash
git clone https://github.com/islamka13/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise install        # инструменты
mise run install    # npm-зависимости
hk install          # git-хуки (pre-commit запускает проверки)
```

## Использование

```bash
mise run dev     # фронтенд http://localhost:5173, API http://localhost:3000
mise run check   # все проверки: линтер, типы, тесты (как в CI)
mise run build   # продакшен-сборка фронтенда
npm run start -w server   # запуск собранного приложения (порт из PORT, по умолчанию 3000)
```
